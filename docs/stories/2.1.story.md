# Story 3.1: Filtros Avançados e Busca na Listagem

## 📝 Descrição da Story
Implementar um sistema de filtragem robusto na página de listagem de imóveis, permitindo que os usuários encontrem propriedades por tipo, quantidade de quartos/banheiros e faixa de preço. O sistema deve ser sincronizado com a URL (Search Params) para permitir compartilhamento de buscas filtradas.

## 🎯 Critérios de Aceitação
- [x] Implementar filtro por Tipo de Imóvel (Casa, Apartamento, Cobertura, Terreno, Comercial).
- [x] Implementar filtro por quantidade mínima de Quartos e Banheiros (1 a 5+).
- [x] Implementar filtro por Faixa de Preço (Min/Max).
- [x] Adicionar campo de busca por texto (título ou localização).
- [x] Sincronizar todos os filtros com a URL via `useSearchParams` e `useRouter`.
- [x] Atualizar a query do Sanity (`PROPERTIES_QUERY`) para suportar todos os novos parâmetros de filtro.
- [x] Adicionar o campo `type` ao esquema de `property` no Sanity Studio.

## 🛠️ Tarefas / Subtarefas
- [x] **Task 1: Atualizar Esquema Sanity**
    - Adicionado campo `type` em `sanity/schemas/property.ts`.
- [x] **Task 2: Atualizar Queries Sanity**
    - Adicionado suporte a `$minPrice`, `$maxPrice`, `$type`, `$bedrooms`, `$bathrooms` em `sanity/lib/queries.ts`.
- [x] **Task 3: Refatorar Componente de Filtros**
    - Atualizado `components/property-filters.tsx` com novos inputs e lógica de sincronização.
- [x] **Task 4: Integrar Busca por Texto**
    - Implementado `PropertySearch` com debounce para filtrar por título/localização.

## 📝 Dev Agent Record
- **Completion Notes**: Sistema de filtros e busca 100% funcional. A listagem agora responde instantaneamente às mudanças de parâmetros na URL, proporcionando uma experiência de busca fluida e profissional.
- **Challenges Encountered**: A query do Sanity precisou ser cuidadosamente ajustada para lidar com valores padrão (ex: bedrooms=0 para "Qualquer").
